# Assignment-native Atlas V3

The October 7, 2026 product brief is the current UX authority. Schoolwork is the
interface: **course → unit → real material → numbered question → explanation →
student work → next question**. It supersedes the earlier primary Learn/Classwork
flow. The source, teacher calibration, account, sync and offline engines remain.

## Student experience

Home offers a resumed assignment and question, upcoming confirmed calendar
items, and current courses. Course pages lead with the current unit and current
material, followed by units, coming up and recent materials. Unit pages list
actual work, notes and resources with completion, plus teacher assessment scope.
There is no normal Learn/Classwork choice or required concept curriculum.

Every published material uses the assignment shell. Overview groups original
checkpoint numbers into compact sections. Focus mounts one question or notes
part at a time. The question, answer field, unit and direction stay in place.
“Help me start” begins deliberate Next/Back reasoning; “Show me more” offers
further scaffolding and a separately requested answer explanation. Written
responses use the reviewed teacher-depth self-check. Easy/Okay/Hard follows
meaningful work, keeping the existing evidence events.

The public questions are reviewed original companions with matching teacher
numbering. Students keep the original for exact wording, images, tables and
assigned molecule lists. The redesign does not grant permission to publish raw
handouts, copyrighted textbook pages or private student work. Independent
Chemistry hand-ins remain metadata only, including on focus deep links.

## Teaching data and motion

`src/core/guide.ts` defines typed `Guide`, `GuideStep` and `Fact` data. Actions
include highlight, derive, extract, target, formula, transform, substitute,
visual and student. The compiler uses the reviewed question's clues, known
values and relationship; it falls back to its existing reasoning when a full
formula model cannot be supported. Every checkpoint has a V3 interaction.

The teaching components are composable:

- `StoryStage`: persistent question wording, clue highlighting and a cumulative
  known/unknown board.
- `useTeachingMotion`: bounded FLIP snapshots and named source-token copying,
  animated with the browser Web Animations API.
- `EquationStage` and `MathToken`: stable addressable equation tokens, proper
  subscripts, fractions, squares and square roots.
- `DiagramStage`: progressive SVG fossil layers, half-life and endosymbiosis;
  conversion factors and cancelling units; electron/bond construction and bent
  water geometry; phrase components and connections.
- `KanaStage`: one selected class vowel and authentic licensed stroke paths,
  with explicit stroke controls and four-square writing context.
- `MicroConcept`: a short sheet returning to the same question and draft.

`src/core/equation.ts` uses a small expression tree. Original, isolated and
substituted frames share token IDs. Operators and variables change position;
known measurements copy into their variable slots. Negative substitutions keep
parentheses. A guide stops at the calculation or written response. Formula fit
uses the available quantities and explains missing ones. It does not derive an
equation from guessed private source content.

### Reference material

Kinematics Review retains `kinematics-review` and its 37 question/subpart IDs.
Question 10 uses the existing companion: a ball dropped for 2.0 s, ignoring air
resistance. “Dropped” produces starts from rest and initial velocity zero;
gravity and elapsed time become known values, the final velocity is identified,
and `vf = vi + aΔt` receives the values. This material uses 9.8 m/s². Wadson's
written vector direction check is unchanged. Question 11 demonstrates square
root isolation for fall time; question 4 moves a denominator while isolating
time. Tests independently evaluate every full physics setup against its reviewed
solution.

C17 notes correlate index fossils across schematic layers and halve isotope
amounts over equal intervals. Section 17-2 question 4 builds endosymbiosis
evidence before the student writes. Bleecker's test scope and resource links
remain attached to the unit.

Hebden introduction and metric conversion work builds factors and cancels only unit symbols.
Hebden p.188 #86 uses an explicitly labeled H₂O worked model to illustrate
electron counting, bonds, lone pairs and bent molecular shape. Students then
return to the textbook's exact assigned species; the model does not invent that
list. Existing Cote/Hebden and separate Glencoe source identities are preserved.

Current Japanese greetings separate おはよう / ございます and ありがとう /
ございます, linking the recurring polite component inside the material.
The five confirmed vowel kana use the existing KanjiVG paths and license.

## Progress and compatibility

V3 adds `checkpoint_saved` snapshots (answer, unit, direction, guide position,
help state and completion) and `material_completed` events. They use the existing
guest/account storage scopes, SQLite JSON event table and idempotent sync API.
There is no destructive database or ID migration. Text writes are debounced and
flushed before navigation, blur, page hide and unmount. A pending local edit is
not overwritten by incoming sync. Scope changes discard only the previous
scope's in-memory draft.

Sync batches retain the API's existing 128 KiB body limit and budget UTF-8 JSON
bytes, so a queue of long multilingual responses does not become unsyncable.

Material completion is explicitly controlled and separate from mastery. Existing
completed section tasks still count; existing correct checkpoint attempts still
count when no newer explicit snapshot exists. Students can mark an assignment
incomplete even after prior completion. Finishing checkpoints suggests completion
without forcing the assignment status.

Existing `/work/<id>/#q-<id>` links open that checkpoint. `?focus=1` restores the
last checkpoint. Old unit `?view=learn` and `?view=classwork` resolve to the same
canonical material list. Legacy course Learn/Work destinations redirect there.
Concept and practice URLs remain available for existing links, search, contextual
help and secondary review. Opening a unit does not generate a concept-view event.

## Accessibility, mobile and performance

Reduced motion uses the same model, DOM and reasoning states, with instant
transforms. No fact requires observing motion. Keyboard arrows advance guide
steps outside editable fields and dialogs. Sheets retain focus return behavior.
Mobile layouts use full-width stages, wrapped data/factors, large controls and a
bottom guide action area while explaining. At the student handoff, the physics
chooser contracts to the setup, the original question stays in view, and real-question
navigation follows the answer and completion controls without covering them.
Light, graphite dark and restrained course accents are preserved.

Only the focused checkpoint renders its teaching scene. Overview is a compact
list rather than hundreds of expanded panels. Motion snapshots are limited to
the active stage. There is no new animation framework or explanation video asset.
Profile the production build, not only the dev server. A laptop/phone viewport
test is browser emulation; physical iPhone or Safari performance requires those
devices and must not be claimed from Chromium results.

## Verification and source boundary

Run `npm run check` and `npm audit --audit-level=high`. V3 tests cover material
routes, completion, focus/overview, extraction, formula token continuity,
substitution, exact-question return, saved answers, evidence ratings, reduced
motion, narrow layouts, sync, offline, restrictions and legacy history. Existing
Wadson direction, percent error and Bleecker scope tests remain.

`scripts/v3-visual-qa.ts` captures 16 reference scenes at 1920×1080, 1440×900,
1366×768, 390×844 and 360×800 in both themes, plus reduced-motion captures at
1440 and 360. It records errors, overflow and DOM counts and creates a local
gallery/contact sheets in ignored `evidence/v3-visual`. Screenshots must be
manually inspected; an automated capture is not a visual review.

The 306-source intake evidence, canonical private registry and hashes, 50
material entries and 353 question checkpoints remain authoritative. Re-run intake
only for new source work. Never read or modify `06 My Notes`. Raw materials,
runtime accounts, answers, cookies, database/backup files and credentials remain
outside public Git/build contexts.

Deployment and coordinated custom-domain instructions live in
[DEPLOYMENT.md](DEPLOYMENT.md). Verify the successful exact main SHA, Pages
`release.json` and API health before claiming deployment. Do not change the frontend
hostname before the backend accepts its origin and secure cookies.
