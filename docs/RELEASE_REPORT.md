# atlas release report

October 5, 2026 · America/Vancouver. The frontend is live; optional online services await a configured home server.

1. **Repository:** [jlsp124/atlas](https://github.com/jlsp124/atlas). Development began private. GitHub rejected private-repository Pages under the account's plan, so the authorized public fallback followed a tracked-history privacy review. Original atlas software/content is MIT licensed.

2. **Frontend:** [Open atlas](https://jlsp124.github.io/atlas/). GitHub Actions deploys the exact successful verification commit. The public release supplies guest/local learning; it does not claim a connected API.

3. **Architecture:** Astro static pages, TypeScript/Zod content, React islands, KaTeX, Pagefind and contextual Cytoscape graphs. Shared course concepts are separate from Fall 2026 editions, teacher pacing and deadlines. An optional Fastify/SQLite WAL service on Node 24.21.0 adds accounts, UUID event reconciliation, admin aggregates and a private request inbox.

4. **Backend deployment:** Follow [Linux deployment](DEPLOYMENT.md). Docker Compose binds only to `127.0.0.1:8787`, persists a private data volume and supports an existing HTTPS proxy/tunnel. Configure `.env.server`, start Compose, verify health, bootstrap Jovan with a unique interactive secret, and test consistent backup restoration. A systemd alternative is included. Configure `PUBLIC_API_URL` and a dedicated support email only after deployment. Same-parent frontend/API domains are recommended because browsers may block cross-site cookies. No server, DNS or tunnel was changed.

5. **Features:** Once/skippable onboarding and a real contextual tour; course selection and useful upcoming work; original assignment checklists; explanations, worked examples, math and annotations; contextual graph/list navigation; ten practice modes; explainable evidence and independent coverage; nearest prerequisite repair, retry and known-to-target paths; tutor prompt copying; Japanese production; search; themes; an installable static cache; isolated guest/account progress and offline event queuing. Optional accounts, deletion, sync, consented aggregates, authorized admin and request status workflows are implemented and tested.
